# Code of conduct

## The short version

Be decent. Assume the other person is trying to help.

## What is expected

Technical disagreement is welcome and is most of what a project like this is
for. Disagree with the code, the design, the trade-off — as sharply as you like.
Do not disagree with the person.

Concretely:

* **Argue about the thing, not the author.** "This deletes by omission, which the
  README says it must not" is a review. "You clearly did not read the README" is
  not, and it makes the same point worse.
* **Say what you actually mean.** A vague objection wastes both people's time.
  If you think something is wrong, say what is wrong and what would be right.
* **Take "no" without a fight.** Not every proposal fits. The
  [roadmap](ROADMAP.md) has a whole section of things that were considered and
  declined, with the reasoning — that is what a "no" looks like here.
* **Be patient.** This is one maintainer. A slow reply is not a slight.

## What is not

Harassment, personal attacks, or bringing someone's identity into a technical
argument. Sustained disruption after being asked to stop. Publishing anyone's
private information.

## If something goes wrong

Report it to the maintainer listed on the repository profile. Reports are handled
privately.

Consequences scale with the problem: usually a request to stop; for repeat or
serious cases, removal from the project's spaces. The maintainer decides, and
will say why.

## Scope

Issues, pull requests, discussions, commit messages, and anywhere someone is
representing this project.
